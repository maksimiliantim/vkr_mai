# PINN-модель динамики киберугроз

Репозиторий содержит код, обученные модели, таблицы с предсказаниями и
итоговые метрики для экспериментов по реконструкции динамики киберугроз с
использованием физически информированной нейронной сети.

Модель не пытается воспроизвести каждый пик временного ряда через пооконный
обучаемый форсинг. Она рассматривается как инструмент регуляризованной
реконструкции базовой динамики, идентификации параметров и анализа невязки.

Версия v2 расширяет предыдущий вариант: состояние `I(t), D(t)` теперь
аппроксимируется не только по сырому времени `t`, но и по детерминированным
Fourier-признакам времени. Это повышает выразительность модели без введения
обучаемого параметра на каждое временное окно.

Ключевые отличия от старого кода:

- вход нейросети: нормированное время `t` и Fourier-признаки времени;
- внешний форсинг `u(t)` задаётся гладкой низкочастотной функцией, а не одним
  параметром на каждое временное окно;
- физический штраф ОДУ используется как мягкая регуляризация, а не как
  механизм подгонки каждого локального всплеска;
- отдельно считаются метрики для `reconstruction`, `holdout` и `forecast`;
- `forecast` оставлен как диагностический режим, но основной вывод диплома
  лучше строить по `reconstruction` и `holdout`, потому что тема работы
  связана с реконструкцией, идентификацией параметров и анализом невязки.

## Интерпретация

`R²` относится только к наблюдаемой компоненте `D(t)`. Для латентного риска
`I(t)`, внешнего форсинга `u(t)`, параметров `β`, `γ`, `κ`, `δ` и невязки ОДУ
нет прямых эталонных наблюдений, поэтому для них `R²` не рассчитывается.

## Особенности реализации

По сравнению с исходной экспериментальной версией добавлены:

- Fourier-признаки времени для аппроксимации `I(t)` и `D(t)`;
- отдельный параметр `n_state_harmonics` для выразительности состояния;
- дополнительный мягкий штраф `lambda_d_smooth` на гладкость восстановленной `D(t)`;
- настройка `dataset`, чтобы корректно подписывать результаты 2017 и 2018 годов.

## Итоговая настроенная конфигурация для CIC-IDS2017

После проверки нескольких вариантов выбрана конфигурация:

- `hidden_dim = 128`;
- `n_layers = 5`;
- `n_harmonics = 12`;
- `lambda_ode = 0.0003`;
- `lambda_ic = 0.1`;
- `lambda_forcing = 0.0003`;
- `lambda_smooth = 0.01`;
- `peak_weight = 3.0`.

Эта конфигурация повышает внимание к пиковым участкам ряда, но не возвращает
старый механизм пооконного запоминания.

## Финальные значения

| Режим | Train R² | Test R² | Комментарий |
|---|---:|---:|---|
| CIC-IDS2017 reconstruction | 0.8710 | - | восстановление всего ряда |
| CIC-IDS2017 holdout | 0.8698 | 0.8681 | каждое 5-е окно исключается из data-loss |
| CSE-CIC-IDS2018 reconstruction | 0.9302 | - | восстановление всего ряда |
| CSE-CIC-IDS2018 holdout | 0.9468 | 0.8731 | каждое 5-е окно исключается из data-loss |

Для диплома лучше опираться на holdout-значения, потому что они показывают
качество на отложенных временных окнах:

- CIC-IDS2017: `R² = 0.8681`;
- CSE-CIC-IDS2018: `R² = 0.8731`.

Прогноз будущего блока не является основной задачей работы и не должен
подаваться как главный результат. Основная постановка: реконструкция,
идентификация параметров и анализ невязки ОДУ.
